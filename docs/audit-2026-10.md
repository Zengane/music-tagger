# Audit — 2026-10-01

Read-only audit of commit `ddc26c5` ("music map skips sound effects; Premiere
button always on; faster launch"). Nothing was built or run. Each finding was
checked by reading the code. Line numbers are for `ddc26c5`.

The music map work in `map_job.py` and `ui/musicmap.odin` is out of scope; it
was fixed in `ddc26c5`.

Severity: **High** = crash, data loss or wrong file changed. **Medium** = wrong
result, a freeze, or large waste of time. **Low** = small or cosmetic.

## 1. Correctness

### 1.1 Delete dialog acts on the wrong file after a rescan — High

- **Where:** `ui/app.odin:2367` (menu opens the dialog), `ui/app.odin:962-963`
  (Delete button calls `delete_chosen_tracks`), `ui/scan.odin:165-171`
  (`forget_track_indices`), `ui/app.odin:312` and `ui/app.odin:437-441`.
- **What is wrong:** The dialog does not store which files to delete. At
  confirm time `delete_chosen_tracks` reads `app.selection` and `app.selected`.
  A finished rescan clears both and does not close this dialog (only
  `.Edit_Marker` is closed). Then `draw_app` sets `app.selected =
  search.view[0]` when the preview panel is open (the default).
- **Failure case:** Start the app. The launch rescan runs in the background
  (`open_last_library`, `ui/libraries.odin:199`). Right-click a file, choose
  Delete file. The rescan finishes. Press Delete. The first file in the list
  goes to the recycle bin. With 40 files selected, the dialog says "Delete 40
  files?" and deletes one other file.
- **Fix:** Copy the target paths into the dialog state when it opens. Delete
  by path. Also close `.Confirm_Track_Delete` (and other index-based dialogs)
  in `forget_track_indices`.

### 1.2 `clone_track` misses three strings — High

- **Where:** `ui/library_cache.odin:74-100`. Used by `load_library_snapshot`
  (`:54`) and `merge_scan_result` (`ui/scan.odin:413,415,429`).
- **What is wrong:** `out := t` copies the string headers for `caption`,
  `ocr` and `text_hay`, but the clone does not copy their bytes.
  - Snapshot load: the source is unmarshalled into the temp allocator
    (`:47`). The main loop frees it on the first frame (`ui/app.odin:303`).
  - Rescan merge: dirty or saved tracks are cloned from the old library,
    then `free_library(&lib)` (`ui/scan.odin:121`) destroys that arena.
- **Failure case:** Analyze a folder of images (captions arrive, tracks are
  dirty). Do not save. Press Rescan, drop a folder in (additive scan), or
  file tracks. The preview panel then reads released memory: crash, or
  garbage. If it does not crash, Save writes the garbage as the caption into
  the sidecar (`ui/tagger.odin:508`). At launch, search over captions reads
  freed memory until the background scan ends.
- **Fix:** Clone `caption` and `ocr` in `clone_track`, then call
  `rebuild_text_haystack(&out, alloc)`. Also remove the duplicate
  `media_kind` clone (`:76-77`). Add a selftest: clone, free the source
  arena, read the caption.

### 1.3 Crash when a file above a playing video is deleted — High

- **Where:** `ui/library_forget.odin:22-23`, `ui/video.odin:185-188`.
- **What is wrong:** `forget_track` moves `player.track` down by one but not
  `video.index`. `video_update` then indexes `lib.tracks[video.index]`.
- **Failure case:** Play the last file in the list, a video. Right-click any
  file above it, Delete. Next frame: `video.index == len(lib.tracks)`.
  Odin's bounds check stops the program. If the video is not last, its
  length is written to another track, and the panel loses the playing
  picture.
- **Fix:** In `forget_track`: `if video.index == index { video_close() }
  else if video.index > index { video.index -= 1 }`. Better: key the video by
  path, not index.

### 1.4 Filing and unsaved tags — High

- **Where:** `ui/filing.odin:95-106` (moves come from in-memory tags),
  `:117`, `:146` (no save first, no job check), `:225` (`start_scan`),
  `ui/scan.odin:51` (scan refused while a job runs), `ui/scan.odin:427-429`
  (merge keeps dirty tracks whose path is gone).
- **What is wrong:**
  1. Filing moves files by their unsaved tags, but does not save first. The
     rescan matches by path. The moved file comes back with its old sidecar
     tags. The old in-memory track is dirty, so the merge keeps it as an
     extra row at the old path.
  2. Filing does not check `job.phase`. If Analyze runs, the rescan after the
     move is refused ("finish or cancel tagging before importing"). The
     library keeps the old paths.
- **Failure case:** Analyze 50 tracks, do not save, "File into library
  folders", Move. The list shows 50 moved files without the new tags and 50
  rows for files that are gone. Save writes 50 sidecars into the old folders
  and creates `.ts` folders there again.
- **Fix:** Save dirty targets (or ask) before the plan. Refuse filing while a
  job runs, or queue the rescan until the job ends.

### 1.5 Snapshot features map frees arena strings on Linux — High on Linux, none on Windows

- **Where:** `ui/scan.odin:79` and `:103` (new in `ddc26c5`).
- **What is wrong:** `path_key(t.path, context.allocator)` returns `p`
  unchanged when `PATHS_FOLD_CASE` is false (Linux, `ui/platform.odin:26`).
  The key is then the library's own arena string. The deferred cleanup calls
  `delete(k)` on it with the heap allocator, after that arena was destroyed.
- **Failure case:** Any rescan on Linux: heap corruption or crash.
- **Fix:** `strings.clone(path_key(t.path), context.allocator)` for the key.

### 1.6 Deleting a track races the waveform worker — Medium

- **Where:** `ui/audio.odin:432-461` (worker reads `lib.tracks[job]`),
  `ui/library_forget.odin:12-36` (`ordered_remove` with no `wave_quiesce`).
- **What is wrong:** The worker holds `t := &lib.tracks[job]` while it
  decodes. `forget_track` shifts the array under it. `peaks_store(t, p)` then
  reads the next file's path, size and mtime. `wave.ready` and `wave.want`
  also keep the old index.
- **Failure case:** Click a long track (decode takes a second), then delete a
  file above it. The next file's cache gets this file's peaks and features
  (hit, drop, tempo). That file then shows the wrong waveform and sends wrong
  markers to Premiere, until its size or date changes. Also: the playing
  track can stay on "reading waveform".
- **Fix:** Call `wave_quiesce()` at the top of `forget_track`. Better: the
  worker takes a `Peak_Key` copy (as the warm-up pool does), not an index.

### 1.7 stderr mixed into binary output — Medium

- **Where:** `ui/subprocess_windows.odin:116-117` (`hStdError = write_pipe`),
  `ui/subprocess_posix.odin:116-117` (same). The comment at
  `ui/subprocess_windows.odin:65-66` says stderr is discarded; it is not.
- **What is wrong:** `peaks_generate_for` (`ui/audio.odin:272-279`) reads raw
  f32 PCM from ffmpeg's stdout with `-v error`. A damaged MP3 makes ffmpeg log
  decode errors at error level. That text lands inside the PCM. The samples
  after it are shifted by a non-multiple of 4 bytes, and the exit code is
  still 0.
- **Failure case:** A file with a few bad frames gets a noise waveform and
  wrong features. They are cached in `cache/peaks` and never rebuilt.
- **Fix:** Add a `merge_stderr` flag to `stream_start`. For binary output,
  send stderr to NUL (or its own pipe). Or use `-v quiet` for the PCM decode.

### 1.8 Analyze undo step stays open — Medium

- **Where:** `ui/tagger.odin:91-92` (`undo_begin` at job start),
  `:227` (`undo_commit` at job end), `ui/undo.odin:65-70`.
- **What is wrong:** The step is open for the whole job. Any other tagging
  action calls `undo_begin`, which abandons the job's step. `finish_job` then
  commits nothing. `cancel_analyze` and a failed start (Python missing,
  `:122-128`) also leave the step open.
- **Failure case:** Analyze 300 tracks. While it runs, add one tag by hand.
  After the run, Undo removes only the hand tag. The 300-track run cannot be
  undone.
- **Fix:** Keep the job's captures in the `Job` struct, not in the shared
  `undo.pending`. Commit them as one step in `finish_job` and in
  `cancel_analyze`.

### 1.9 One unreadable folder fails the whole scan — Medium

- **Where:** `ui/scan.odin:258-264`, `:143-147` (any `scan.err` discards the
  result).
- **What is wrong:** If `os.open` or `read_directory` fails on any subfolder,
  the worker sets `scan.err`. `poll_scan` then throws the whole result away.
- **Failure case:** A library at a drive root. `System Volume Information`
  cannot be opened by a normal user. Every scan says "could not read a
  folder; keeping the current library". Same for one folder with broken
  permissions.
- **Fix:** Log and skip unreadable subfolders. Fail only when the root
  itself cannot be read.

### 1.10 Selection drag reuses the wrong cached file — Low

- **Where:** `ui/waveform.odin:595-640`.
- **What is wrong:** `app.clip_path` is filled by either branch (a WAV
  placeholder when the panel answers, an FCP7 `.xml` when not) and reused by
  the other. Only the mode toggle and a selection change clear it.
- **Failure case:** Drag a range with Premiere closed (XML written). Open
  Premiere and drag the same selection again. The XML is dragged, and the
  `/swap` call looks for a clip made from the XML. It fails.
- **Fix:** Store what kind of file `clip_path` holds. Clear it when the kind
  needed changes.

### 1.11 Other small items — Low

- `ui/app.odin:2359-2362`: the right-click "Send to Premiere" sends only the
  right-clicked file when many are selected.
- `ui/fcpxml.odin:41-43`: on macOS and Linux the URL becomes
  `file://localhost//home/...` (two slashes). Strip a leading `/`.
- `ui/premiere.odin:257` `trim_in_premiere` has no caller. The panel's
  `/trim` route is unused by the app. Remove it or document it.
- `ui/video.odin:379`: `video.audio_done` is written by the audio thread and
  read by the main thread without an atomic. Use `sync.atomic_store/load`.
- `ui/library_forget.odin:19-20`: deleting 200 files restarts the search
  server and unloads every thumbnail texture 200 times. Do it once after the
  loop in `delete_chosen_tracks`.

## 2. Performance

### 2.1 Long videos freeze the window — Medium

- **Where:** `ui/video.odin:103-121` (`video_close` joins the audio thread),
  `:378-392` (whole soundtrack to a WAV), `:191-193` (whole WAV read on the
  main thread).
- **Failure case:** Click a one-hour video, then click another track within
  a minute. `play_track` → `unload_music` → `video_close` waits until ffmpeg
  has written about 690 MB of WAV. Later, that WAV is read into RAM in one
  call on the drawing thread.
- **Fix:** Do not join a running conversion: let it finish detached, or kill
  ffmpeg and delete the temp file. Stream the sound instead of loading it
  whole (for example a compressed `.ogg` cache, which raylib streams).

### 2.2 First play of m4a and 24-bit WAV blocks the window — Medium

- **Where:** `ui/audio.odin:560-577` (`playable_path` runs ffmpeg on the
  main thread), `:629` (whole file read into memory).
- **What is wrong:** About a third of the library (m4a, and WAVs that are
  not 16-bit) is converted on the drawing thread at first play.
- **Fix:** Convert on the waveform worker or a small pool. Show "preparing"
  until it is ready.

### 2.3 Effects tagging re-embeds every file on every run — Medium

- **Where:** `sfx_job.py:240-249`.
- **What is wrong:** With PE-AV (Balanced and Best), `zs_text` is set, so
  `cached` is always `None`. Every file goes through PE-AV again, even when
  its vector is cached. AST and PE-AV are also both resident, file by file.
  The audit of 2026-09-24 (§4) items are still open: one file per model call,
  and two decodes per file (16 kHz in `A.decode`, 48 kHz in `A.windows`).
- **Fix:** Cache the raw window mean next to the pooled vector (or the
  per-tag probabilities). Then run the job model-major, like
  `FusionEncoder.prefill`: AST over all files, unload, PE-AV over the
  uncached ones.

### 2.4 Search server holds up to five models — Medium

- **Where:** `search_server.py:65-134`, `IDLE_MINUTES = 20` (`:36`).
- **What is wrong:** One query can load SigLIP 2, E5, CLAP-music, PE-AV and
  CLAP-sfx, each with its audio or image tower, only to embed text. They stay
  on the GPU for 20 minutes. An Analyze run at the same time then competes for
  VRAM. That is the 8 GB spill that `FusionEncoder.prefill` was written to
  avoid. The server is also restarted on every rescan and every deleted file
  (`ui/scan.odin:180`, `ui/library_forget.odin:20`), and each start reads one
  `.npy` per file per space (`mtag/semantic.py:89-121`).
- **Fix:** Load only the text towers (CLAP's `get_text_features` needs only
  its text model). Unload models after a
  short idle (1–2 minutes), or pause the server while a job runs. Restart on
  delete only when the library is idle.

### 2.5 PDF and 3D thumbnails start one Python per file — Medium

- **Where:** `ui/thumbs_render.odin:27-31` asks for `.Pages`;
  `preview_job.py:63` renders up to 40 pages at 1400 px; `ui/preview.odin:356`
  starts Python once per file.
- **Failure case:** A folder of 200 PDFs in tile view starts 200 Python
  processes and renders up to 8000 pages, to make 200 thumbnails.
- **Fix:** Add a `first-page` mode for thumbnails. Keep one preview worker
  process alive and feed it paths, as the search server does.

### 2.6 Work on the drawing thread after the warm-up — Low

- **Where:** `ui/app.odin:320-325` → `load_all_features` (`ui/warmup.odin:104`).
- **What is wrong:** When the warm-up ends, every audio track without
  features is read: two file opens each, on the main thread.
- **Failure case:** First import of a large library: a stall of seconds when
  the warm-up finishes.
- **Fix:** Have the warm-up workers return the features with the result, or
  read them on the scan worker.

### 2.7 Smaller items — Low

- `ui/thumbs.odin:180-195`: the thumbnail queue is never trimmed. Scrolling
  through 10,000 images queues 10,000 ffmpeg runs, most for tiles no longer
  on screen. Cap the queue, or drop jobs not drawn for a few seconds.
- `ui/tagger.odin:307`, `:434`: every result line does a linear path search
  over the library. Build a path→index map at job start.
- `ui/thumbs_render.odin:60`: models are loaded with `rl.LoadModel` on the
  drawing thread; a big glTF stalls a frame. Unsure how large in practice.
- Odin's `read_directory` on Windows opens every file to read its file ID
  (`core/os/dir_windows.odin:26`). The scan pays one `CreateFileW` per file.
  Unsure how much this costs on the owner's drive; measure before acting.
- Open from 2026-09-24 and still open: one `.npy` file per vector; the media
  job loads all three models every run, even when every file is cached
  (`media_job.py:47-70`); fusion decodes each file once per part.

## 3. Premiere integration

### How sending works today (`ddc26c5`)

1. **Buttons.** The player has a Premiere button whenever a track is loaded
   (`ui/app.odin:1878-1903`): the selection if there is one, else the whole
   file. The preview panel has "Send to Premiere" for audio, video and images
   (`ui/inspector.odin:104-120`). The right-click menu also has it
   (`ui/app.odin:2359`).
2. **Request.** `send_to_premiere` (`ui/premiere.odin:195`) sends one HTTP
   GET to `127.0.0.1:<port>`: `/drop?mode=timeline&path=…[&in&out][&mark]`.
   The port comes from Zen Drop's `settings.json`.
3. **Panel.** `client/main.js:183-202` checks the file exists, answers
   "queued", and queues the job. `zdDrop` (`host/host.jsx:635`) imports the
   file or reuses its project item, sets in/out if a range came, and
   `zdPlace` (`:378`) overwrites it at the playhead on the lowest free track
   (or a new track). The marker goes on the project item, in source time.
4. **Drag of a selection** (`ui/waveform.odin:579`): if the panel answers
   `/ping`, a WAV of the selection is dragged, then `/swap` replaces it with
   the original, trimmed. If not, an FCP7 XML range (or a rendered WAV in clip
   mode) is dragged.

### What still blocks or spoils a whole-track send

The UI no longer needs a selection (fixed in `ddc26c5`). What is left:

1. **Stale in/out on a reused project item — Medium (verify in Premiere).**
   `zdImport` reuses an existing project item (`host.jsx:160-163`). `zdDrop`
   sets in/out only when a range is given (`:643`). `zdPlace` then places
   whatever in/out the item already has (`:388-392`). After a range send of a
   file, a whole-track send of the same file can place the old range.
   **Fix:** in `zdDrop`, when no range is given, call `item.clearInPoint()`
   and `item.clearOutPoint()` (or set 0 to the media end) before `zdPlace`.
2. **"Sent" means "queued" — Medium.** The panel answers before the
   ExtendScript runs (`main.js:200`). "No active sequence", "no free track"
   (when the fallback is not "new track") and timeouts show only in the
   panel's log. The app's toast says "sent". **Fix:** add a job id and a
   `/status?id=` route, and poll it from the app, or word the toast as
   "queued in Premiere".
3. **No marker on whole-track sends — Low.** The whole-file path passes
   `mark = -1` (`ui/app.odin:1891-1895`, `ui/inspector.odin:109`,
   `ui/app.odin:2362`), even when the track has a cue, a measured hit
   (effects) or a drop (music). **Fix:** use `mark_for_range(t, 0,
   t.duration)`.
4. **The send blocks the window — Medium.** `http_get` runs on the drawing
   thread with a 5 s receive timeout (`ui/premiere.odin:99-110`).
   `premiere_available()` is also called at the start of every selection drag
   (`ui/waveform.odin:595`). On Windows a refused loopback connection is
   reported to take about 1–2 s because of SYN retries (unsure; measure).
   **Fix:** send on a worker thread; cache the `/ping` answer for a few
   seconds.
5. **Placement length fallback — Low.** If `getInPoint`/`getOutPoint` fail,
   `zdPlace` assumes 5 s (`host.jsx:392`), so a free-space check for a long
   track can pass and the overwrite then covers later clips. **Fix:** use
   the media duration (`item.getOutPoint()` after `clearOutPoint`, or the
   duration from the app as a query value).
